**Обновление по последующей просьбе пользователя:** обычный тезис теперь проверяется как ключевые слова с контекстной связью, а непрерывная точная фраза — только при явных кавычках. Историческое описание строгого режима ниже относится к предыдущей реализации. Текущие правила и ограничения соцсетей описаны в README; регрессия «Аделинчики Саратов» — в VALIDATION.md.

Контекст восстановлен из чатов «Спланировать решение по PDF» и «Создать сайт с Yandex GPT». Сохранён стек Flask + HTML/CSS/JS + SQLite + Yandex Search API + YandexGPT. Последнее ТЗ заменяет прежний смысловой поиск тезиса строгим совпадением. `mode` теперь отвечает за сценарий, `scope` — за расширенный поиск или выбранные источники.

## 2. «Свежее»

**Изменения:** `content.py`, `filters.py`, `jobs.py`, API и форма.

```python
anchor = search.created_at  # фиксированный UTC-момент запуска
accept = anchor - timedelta(hours=24) <= published_at <= anchor
```

Сохраняются часы, минуты и UTC-смещение. Дата без времени или без часового пояса не доказывает попадание в последние 24 часа и при включённом фильтре исключается. Период и свежесть применяются совместно. В сравнении фильтр ограничивает найденные публикации; эталон сохраняется независимо от возраста. В истории метка относится к моменту исходного запуска, при повторе окно вычисляется заново.

**Проверки:** `test_exact_fresh_boundary`, `test_fresh_filter_in_both_modes`: ровно 24 часа, на секунду старше, разные UTC-смещения, будущее, неизвестная дата и отсутствие часового пояса.

## 4. История в БД

**Изменения:** `db.py:migrate`, API истории и повторного запуска, `static/app.js`.

```sql
CREATE TABLE search_history (
  id TEXT PRIMARY KEY REFERENCES searches(id) ON DELETE CASCADE,
  user_id TEXT NOT NULL, mode TEXT NOT NULL, query TEXT NOT NULL,
  region TEXT NOT NULL, city TEXT NOT NULL, fresh_only INTEGER NOT NULL,
  "limit" INTEGER NOT NULL, results_count INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL
);
CREATE INDEX idx_history_user_created ON search_history(user_id, created_at DESC);
```

Добавочная миграция с `BEGIN IMMEDIATE` сохраняет старые данные, переводит старый `mode` в `scope`, заполняет историю через `INSERT OR IGNORE`. Триггеры создают ровно одну строку на запуск и обновляют количество результатов. Повторная доставка фонового задания не запускает обработку второй раз. API возвращает последние 100 записей по убыванию времени. `POST /api/searches/<id>/repeat` восстанавливает все параметры, включая `limit`, город, свежесть и источники.

`user_id` здесь — идентификатор подписанной cookie-сессии, как было согласовано ранее. Регистрации пользователей нет. Очистка cookies лишает браузер доступа к прежней истории. Все чтения/повторы проверяют владельца.

**Проверки:** `test_history_repeat_limit_and_owner`, `test_migration_preserves_existing_history`, прежние тесты изоляции и Excel. Также миграция дважды выполнена на копии существующей БД. Резервная копия до запуска новой версии — `artifacts/pre-search-upgrade.sqlite3`.

## 9. Точное совпадение

**Изменения:** новый `matching.py`, зависимость pymorphy3 и словарь OpenCorpora, `search_terms`, фильтр в `jobs.py`.

```python
morph = MorphAnalyzer(units=[DictionaryAnalyzer()], char_substitutes={})
# Только соседние полные токены. Между ними — пробелы, а не другие слова/предложения.
match = exact_token or same_unambiguous_dictionary_lemma
if not phrase_match(query, original_or_fetched_title):
    discard()
```

Отключены предсказания неизвестных слов и подмена ё/е. Оценки словарных разборов суммируются по лемме: при уверенности не менее 0,9 выбирается основная лемма (например, «дороги» → «дорог», «дорогах»). При неоднозначности слова запроса применяется буквальное совпадение; неизвестные слова также только буквальные. В запросе Яндекса используется фраза в кавычках, `fixTypoMode=OFF`; окончательная проверка выполняется по полученному оригиналу/его заголовку, не сниппету. Модель не переписывает тезис. Фраза до 200 символов; большой текст направляется в сравнение.

**Обязательные тесты:** «пожарная безопасность» и «пожарной безопасности» — да; «правила безопасности», «безопасность движения», разрыв другими словами/предложением — нет. «адресант», «адресанта», «адресанту» — да; «адреса», «адрес», «адресат», «лжеадресант» — нет. Точное совпадение добавляется в объяснение и Excel.

**Граница:** омонимы и смысл утверждения остаются задачей последующей модели/ручной проверки. Словарь сознательно не угадывает неизвестные словоформы.

## 10. Количество и группы

**Изменения:** валидация API, `jobs.py`, `filters.py`, `static/app.js`.

```python
assert type(limit) is int and 1 <= limit <= 100
candidate_budget = min(500, max(configured_budget, limit * 3))
stop_when(saved_results == limit)
groups = group_by_source(results) if len(results) > 50 else []
```

`limit` — верхняя граница результатов, не обещание существования стольких подходящих публикаций. Поиск обрабатывает дополнительные кандидаты после отклонения неподходящих; ограничения покрытия видны пользователю. По умолчанию 20, быстрые значения 10/20/50/100, своё целое число. VK группируется по числовому ID стены; для сайтов используется домен, для ОК/MAX — путь сообщества. Группы показывают источник, число и ссылки внутри раскрываемого списка. Выбор для Excel работает и в группах.

**Проверки:** `test_new_parameter_validation`, `test_history_repeat_limit_and_owner`, `test_large_result_grouping_and_labels`; браузер — 60 записей, раскрываемые группы, 3 записи при повторе соответствующего поиска.

## API-пример

```json
{
  "mode": "by_thesis", "scope": "extended",
  "query": "пожарная безопасность",
  "region": "Красноярский край", "city": "Норильск",
  "fresh_only": true, "limit": 50,
  "date_from": "2026-10-01", "date_to": "2026-10-19",
  "platforms": ["web", "vk"], "source_ids": []
}
```

`POST /api/searches` возвращает ID; `GET /api/searches/<id>` — условия, публикации и группы. `GET /api/searches` — история текущей сессии. POST требует прежний CSRF-заголовок. Совместимость со старыми `mode=extended|sources` сохранена на входе, наружу возвращаются новые значения.
