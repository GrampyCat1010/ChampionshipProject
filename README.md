# Медиаподборка

Веб-приложение медиамониторинга для кейса Агентства печати и массовых коммуникаций Красноярского края. Flask + HTML/CSS/JavaScript + SQLite; обнаружение публикаций через Yandex Search API, смысловой отбор через YandexGPT 5.

## Запуск

Нужен Python 3.12+. Node.js для работы сайта не требуется.

Windows / PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# Заполните .env. Если он уже существует, не перезаписывайте его.
.venv\Scripts\python.exe app.py
```

В текущей рабочей папке окружение и `.env` уже подготовлены. Для повторного запуска достаточно:

```powershell
.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5000. Можно использовать `start.ps1` или `start.bat`.

Linux:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
# Заполните .env, затем:
.venv/bin/python app.py
```

Сервер — Waitress, без Flask debug/reloader. При первом запуске автоматически создаются SQL-таблицы и локальный секрет сессий в `instance/`. Используйте **один процесс приложения**: два фоновых потока исполняют задания, SQLite хранит результаты. Запуск нескольких процессов требует отдельной очереди и координации восстановления заданий; в этом прототипе не поддерживается.

## Настройки .env

| Переменная | Назначение |
| --- | --- |
| `YANDEX_CLOUD_FOLDER` | Folder ID каталога Yandex Cloud |
| `YANDEX_CLOUD_API_KEY` | Ключ YandexGPT; используется и поиском, если отдельный ключ не указан |
| `YANDEX_CLOUD_MODEL` | По умолчанию `yandexgpt-5-pro/latest` |
| `YANDEX_SEARCH_API_KEY` | Отдельный ключ поиска, необязательный |
| `SECRET_KEY` | Постоянный случайный секрет Flask; если пустой, создаётся локальный `instance/session.key` |
| `DATABASE_PATH` | По умолчанию `instance/mediapodborka.sqlite3` |
| `MAX_CANDIDATES` | Максимум кандидатов за запуск, 1–100; по умолчанию 30 |
| `SEARCH_PAGES` | Страниц выдачи на запрос, 1–3; по умолчанию 1 |
| `HOST`, `PORT` | По умолчанию `127.0.0.1:5000` |
| `COOKIE_SECURE` | `true` при работе через HTTPS; локально `false` |

Ключу нужны действующие права для соответствующих сервисов: `ai.languageModels.user` и `search-api.webSearch.user`, разрешения `yc.ai.languageModels.execute` и `yc.search-api.execute`, доступный баланс. Ключ хранится только на сервере. `.env`, окружение, база, логи и артефакты проверки исключены через `.gitignore`. `.env.example` не содержит секретов.

Проверка доступа (выполняет два небольших платных API-запроса по тарифу аккаунта):

```powershell
.venv\Scripts\python.exe -X utf8 scripts/check_services.py
```

## Что работает

- Поиск темы, события, человека или пересказов исходной новости.
- Период публикации, регион, выбор VK / ОК / MAX / сайтов.
- Расширенный поиск и поиск по выбранным источникам из пользовательского списка.
- Добавление, редактирование и удаление источников без изменения конфигурации.
- Фоновая обработка, промежуточные результаты, история, восстановление доступа к сохранённому результату.
- Получение оригинала, консервативное извлечение текста и даты, отдельное хранение сниппета.
- Отбор YandexGPT: подходит, не подходит, на проверку; объяснение, цитата и основание региональной связи.
- Проверка, что цитата действительно присутствует в оригинале (допустимы только различия пробельной разметки).
- Выбор и исключение публикаций, текстовый фильтр, просмотр сохранённого текста, прямые ссылки.
- XLSX с выбранными публикациями, кликабельными ссылками и вторым листом условий/покрытия.
- Изоляция рабочих пространств по подписанной cookie-сессии, CSRF-защита, экранирование содержимого и защита от формул в Excel.

## Правила достоверности и учёта

Сниппет поиска не является оригиналом. Недоступный оригинал, неизвестная дата или непроверяемая цитата не попадают автоматически в выбранную подборку. Пользователь может включить спорный материал вручную; соответствующий статус сохраняется в Excel.

«Подходит» означает содержательную связь, а не доказанную правдивость. Независимая проверка фактов и рейтинг «достоверных / недостоверных сайтов» не реализованы: один текст не даёт достаточных оснований для таких выводов. Поле проверки утверждений честно сообщает об этом.

Дата публикации берётся из структурированных метаданных/тега времени, не из времени загрузки и не выдумывается моделью. Границы периода проверяются после загрузки оригинала. Совпадение слов или принадлежность СМИ к региону сами по себе не подтверждают связь с событием.

Каждое размещение имеет собственный нормализованный URL. UTM-метки и обёртки VK не увеличивают счётчик; одинаковый текст на разных адресах остаётся отдельными размещениями. Группировка сейчас обнаруживает только точные копии нормализованного текста, не все смысловые пересказы.

После изменения формы показанная подборка остаётся привязанной к прежнему запуску: её условия написаны над результатами. Excel включает **все отмеченные материалы текущего запуска**, даже скрытые фильтром. Ошибка источника не удаляет уже полученные материалы. Повтор создаёт новый запуск с теми же условиями, прежний результат сохраняется.

## Реальные ограничения

- **Прямые API VK, ОК и MAX не подключены.** Обнаружение идёт через индекс Яндекса, чтение — через публичные HTML-страницы. Сбор всех трёх соцсетей в объёме исходного кейса не подтверждён. Авторизация, динамические страницы, CAPTCHA, robots/политики площадок и неполный индекс ограничивают доступ. Защитные страницы не обходятся.
- Поиск по выбранным источникам — поиск по их адресам в индексе, а не полный обход всех публикаций группы. Для точного сопоставления VK используйте `club123` / `public123`; принадлежность постов по произвольному короткому имени автоматически не разрешается.
- Нет гарантий полноты. Показываются выполненные запросы, ошибки и лимиты. Стартовый список групп не выдуман — пользователь добавляет реальные источники.
- Модель видит до 16 000 символов оригинала, сохранение текста ограничено 60 000 символами, HTML-ответ — 2 МБ. Лимиты затрат: до 100 кандидатов, 20 источников за запуск, 20 поисков в час на браузерное пространство, очередь до шести заданий, два исполнителя.
- Нет регистрации и общей командной учётной записи. Очистка cookies теряет доступ к пространству из браузера; данные остаются в SQLite. Для публичного размещения нужна внешняя авторизация/ограничение доступа и общий лимит расходов — сессионный лимит не защищает бюджет от создания новых сессий.
- Перезапуск сервера помечает незавершённые задания как прерванные. Уже сохранённые результаты доступны, запуск можно повторить.
- Не реализованы: аналитическая записка, тональность, импорт XLSX-источников, уведомления и полноценный фактчекинг. Они не входят в обязательный сквозной сценарий документа.

## Проверка

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

Тесты используют изолированные временные базы и подменённые ответы сервисов: учёт повторов, разные размещения, даты, отсутствие оригинала, ошибки, контроль принадлежности источнику, сессии, CSRF, проверяемая цитата и XLSX. Это не доказательство интеграции соцсетей.

Для отдельной живой проверки до четырёх публичных материалов (использует платные API):

```powershell
.venv\Scripts\python.exe -X utf8 scripts/live_smoke.py
```

Отчёт и отдельная SQL-база находятся в игнорируемой папке `artifacts/`; XLSX создаётся, если есть автоматически отобранные материалы. Конкретная выдача и доступность внешних страниц меняются.

## Развёртывание

Проект готов к локальному запуску; на внешний сервер автоматически не установлен. Для установки используйте отдельную директорию, Python 3.12+, зависимости, собственный `.env`, постоянный каталог `instance/` и один процесс Waitress под менеджером служб. Публикуйте через HTTPS reverse proxy и ограниченный доступ команды. Не открывайте `.env`, `instance/` или корень проекта как статическую директорию; Flask отдаёт только `static/`. Резервируйте SQL-базу вместе с `instance/session.key` с помощью SQLite backup API или после остановки сервера (простое копирование одного файла при WAL может потерять записи).

Запрос пользователя передаётся Yandex Search API; запрос и извлечённый текст публикаций — YandexGPT. Внешние страницы получают обычный запрос на чтение без ключей Яндекса. Тарифы и хранение данных определяются используемыми сервисами. Расходы не фиксируются приложением; настройте бюджет каталога Yandex Cloud.

Документация: [Yandex Search API](https://aistudio.yandex.ru/ru/docs/search-api/api-ref/WebSearch/search), [OpenAI Python SDK](https://github.com/openai/openai-python), [Flask](https://flask.palletsprojects.com/).
